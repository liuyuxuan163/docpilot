# DocPilot

**企业知识库问答 Agent** —— 一个刻意做小的 RAG 项目：单文件 ReAct 主循环、零核心第三方依赖、一条命令跑通。
它要证明的不是"能答问题"，而是**答得可信**：每条结论能指回原文、没依据时明确拒答、无权限的内容检索阶段就看不到。

```bash
python -m docpilot demo     # 6 个典型场景，不需要 API Key
```

---

## 这个项目解决什么问题

企业内部的文档问答有一个共性难点：**模型很会编，但企业答错一句话是要负责的。**

所以本项目的核心不是"答得更花哨"，而是三条底线：

| 底线 | 为什么重要 | 本项目怎么做到 |
|---|---|---|
| **不编** | 用户无法分辨"真读过文档"和"编得像" | 每条结论标 `[n]` 引用，且 `[n] → 文档` 的映射由**框架**生成并校验标号范围 |
| **不知道就说不知道** | 硬凑一个答案比承认不知道危险得多 | 检索证据不足时明确拒答，并说明是"没有依据"还是"无权限" |
| **不该看的看不到** | 权限泄漏是安全事故，不是体验问题 | 文档级权限过滤在**检索阶段**生效，无权限片段根本不进入上下文 |

## 60 秒跑起来

```bash
cd DocPilot
python -m docpilot info     # 环境自检
python -m docpilot demo     # 演示 6 个典型场景
python -m pytest tests -q   # 259 个测试
python -m docpilot eval     # 跑评测 + 质量门禁
```

**不需要 API Key，不需要向量数据库，不需要 `pip install` 任何东西。**
核心运行时只用 Python 标准库（3.9+）。

想接真实模型：把 Key 写进 `.env`，用命令行只切换这一次。

```bash
cp .env.example .env          # 然后只填一行 DEEPSEEK_API_KEY=sk-xxxx
python -m docpilot info       # 会告诉你 provider / key 分别来自哪一层
python -m docpilot ask "年假可以结转到明年吗" --provider deepseek
```

配置优先级是 **命令行 > 真实环境变量 > `.env` > `configs/docpilot.yaml`**，所以：

- `.env` 里保持 `DOCPILOT_PROVIDER=mock` 时，`pytest` / `eval` / `demo` / `mcp` 全部离线；
- 只有加了 `--provider deepseek` 的那一条命令会调真实接口 —— **默认不联网是硬约束**；
- 反过来，把 `.env` 的 provider 改成 `deepseek` 就是"全局切真实模型"，`eval` 也会真花钱。

> 没配 Key 时系统会**自动降级为 Mock 并提示**，而不是直接报错 ——
> "环境不全也能跑起来"是刻意设计的体验。
>
> `.env` 的解析器是手写的（约 40 行，零依赖），只支持 `KEY=VALUE` / 注释 / 引号 /
> `export` 前缀；**不支持多行值与变量插值** —— 需要就走真实环境变量。

```
▸ ① 常规事实问答　(角色: public)
  问：年假没休完可以结转到明年吗？最多结转多少天？
  答：根据知识库中的以下内容：
      [1] **可以，但有上限。** 当年未休完的年假最多可结转 **5 天**到下一年度，
          超出 5 天的部分在次年 3 月 31 日自动作废，公司不另行折现。
          （来源：hr/leave-policy.md#年假可以结转到下一年吗）
  引用：hr/leave-policy.md#年假可以结转到下一年吗
  指标：约 2217 token · 11 ms · 工具 ['search_docs']

▸ ③ 多轮追问（自动改写问题）
  问：那最多能结转到下一年多少天？
  改写后：结转到下一年最多能多少天？年假
  答：…最多可结转 **5 天**…        ← 正确消解了"那"指代"年假结转"

▸ ④ 超纲提问（应当拒答，不编造）
  问：今天天气怎么样？
  答（拒答）：检索结果与问题的实义字符覆盖率仅 0.20，且没有明显突出的片段，
              说明问题在知识库中没有对应依据，因此我不做推测。

▸ ⑤ 权限隔离（public 角色看不到薪酬文档）
  问：P4 职级的绩效工资占比是多少？
  答（拒答）：这个问题涉及受限文档（`hr/compensation.md`），你当前角色（public）
              没有访问权限。请联系对应文档的负责人申请授权，
              **我不能用其它文档的内容代替回答。**

▸ ⑥ 权限内提问（hr 角色可以看到同一份文档）
  问：P4 职级的绩效工资占比是多少？
  答：…绩效工资基数占月度总薪酬的 20%~35%，按职级确定：P4-P6 → 30%…
  引用：hr/compensation.md#薪酬结构
```

注意 ⑤ 与 ⑥ 的对比：**同一个问题，不同角色得到不同结果**，
而且无权限时的回答是"你没有权限"，不是拿别的文档含糊作答。

## 实测指标

**评测集**：21 条端到端用例，覆盖 6 类场景（单轮事实 / 口语化 / 多轮追问 / 应拒答 / 权限隔离 / 元问题）。
`python -m docpilot eval` 可复现，且接入 CI 质量门禁。

| 指标 | 实测 | 门禁 | 含义 |
|---|---|---|---|
| **复合分** | **0.931** | ≥ 0.75 | 四项加权 |
| retrieval_hit | 0.952 | ≥ 0.85 | 期望文档是否被检索到 |
| **citation_valid** | **1.000** | ≥ 0.95 | 引用是否真实存在（**无伪造引用**） |
| refusal_correct | 0.857 | ≥ 0.70 | 该拒答时是否拒答 |
| answer_coverage | 0.905 | — | 答案要点覆盖率 |
| **over_refusal_rate** | **0.000** | ≤ 0.15 | **该答却拒答的比例（0 = 从不误拒）** |
| hallucination_rate | 0.143 | — | 该拒却答的比例（**已知边界**，见下） |
| 平均 token | 2,196 | — | 每次问答 |
| P95 延迟 | 67 ms | — | 纯本地检索 |

**其它**：259 个单元测试全绿；检索 top-1 命中率 8/8（人工标注的"该命中哪一篇"回归测试）。

> ⚠ **`hallucination_rate = 0.143` 需要加一句限定：这 21 条里只有 6 条负例，而且大多是
> easy negative（"今天天气怎么样"这种零字面重合的）。** 我另做了一套
> **60 条 hard negative**（与文档里真实存在的事实同构、但文档恰好没答），
> 同一套判定逻辑在它上面的误答率是 **90.0%**（[79.9%, 95.3%]），而正例误拒仍是 **0%**。
> 所以 0.143 的真实含义是"**简单负例上的**幻觉率"，不是系统整体水平。
>
> **但 89.8% 也不是"系统误答率"，而是"词面 gate 的误判率"** —— Mock 把
> `has_evidence` 当唯一依据，gate 一说"有依据"它就把 top-1 片段抄进答案。
> 接真实模型（deepseek-flash）实测 68 条负例（59 主集 + 9 holdout）：
> **人工核对后真误答 0 条**（模型读到片段会自己判断，甚至会二次检索），
> 正例真误拒 1~2/40；同时发现**评测自身的拒答识别依赖措辞**（9 条正确拒答被
> 漏判成作答、3 条正常作答被误判成拒答）。判据必须与话术解耦。
> 复现：`python scripts/build_hard_negatives.py` + `python scripts/eval_stratified.py`。
> 复核结论写在 `data/eval/hard_negatives.review_state.jsonl`（**独立文件**）：
> 生成器每次都会重写 candidates/dev/test，但**永远不写掉这个文件**，
> 所以重跑生成器不会丢掉人工复核结果。状态文件里带语料指纹，
> 语料一改就会警告"复核可能已过期"。

### 为什么 `over_refusal_rate = 0` 值得单独说

拒答机制最常见的失败不是"该拒没拒"，而是**该答却拒**——
一个动不动就说"我不知道"的助手，用户会直接弃用。

所以标定阈值时我把"零误拒"当作硬约束：在 16 条应回答问题 + 9 条应拒答问题的标注集上做网格搜索
（`python scripts/calibrate_thresholds.py` 可复现），**优先保证不误拒**，再在此前提下压幻觉。

结果：25 条标注集上误拒 0 条，残余 3 条幻觉。

**为什么只有三个工具？**
RAG 问答的最小闭环就是「消解指代 → 检索 → 作答」。
工具多了不涨能力、只涨不确定性 —— 这也是本项目刻意不做 Multi-Agent 编排的原因。

**这套东西不止一个前端在用。** 上面那张图是"Agent 前端"；
`KnowledgeBase` 与 `ToolRegistry` 是共用的，所以同一个检索内核被三种方式调用：

| 前端 | 用法 | 谁在决策 |
|---|---|---|
| CLI / Web / Agent | `ask` / `demo` / 网页 | 本项目的 ReAct 循环 |
| **MCP 服务端** | `python -m docpilot mcp` | **宿主的模型**（Claude Desktop / Cursor） |

## 七个值得展开讲的设计决策

### 1. 混合检索，而不是"上向量库就完事"

企业文档里的关键信息往往是**低频精确词**：制度编号（`HR-2024-07`）、金额、时限（`15 个工作日`）、系统名（`SSO`）。
纯向量检索对这类词很弱；而用户又常用口语提问（"年假能攒到明年吗"），纯 BM25 也招架不住。所以两路都要。

融合用 **RRF**，因为它只用**排名**不用**分数**：

```
fused(d) = Σ_r  w_r / (k + rank_r(d))
```

好处是不用纠结 BM25 分数（无界）与余弦相似度（[-1,1]）怎么对齐量纲
（Elasticsearch 等系统默认也用它，`rank_constant=60`）。

**为什么稠密侧用本地嵌入而不是真实 embedding？** 换来三件事：零依赖、零成本、**完全可复现**。
最后一点尤其关键 —— 检索结果不确定，就没法对检索质量写回归测试。

**但更硬的理由是实测出来的**：我做了通道消融（`python scripts/experiment_dense_channel.py`），
**把稠密通道整个关掉，21 条用例的质量指标一个都没变** ——
复合分 0.9310 / 检索命中 0.9524 / 拒答正确 0.8571 / 幻觉率 0.1429，逐例分数也完全相同。
原因是排序主键 `relevance` 与拒答判定 `has_evidence` **都只读词面信号**；
稠密通道唯一独有的 2 个槽位还落在那条已知幻觉 `refuse-03` 上，没改变任何判定。

所以结论不是"本地嵌入够用"，而是：**在这条链路上，"换一个更好的 embedding"不是优化项。**
想动幻觉率，必须先动判定信号（见「已知限制」第 1 条）。只换嵌入再跑一遍评测，
得到的会是"改了很多、指标没动"，然后误以为是自己做错了。反面证据也在这份数据里：
单开稠密时幻觉率反而降到 0.0952，但检索命中掉到 0.9048、误拒从 0 升到 0.0476 ——
**指标对"候选池的组成"敏感，而不是对"语义能力"敏感。**

**同样的机制也解释了 BM25 参数为什么"调了没反应"。** 我把 k1/b/delta 做了 16 组单变量
敏感度实验（`python scripts/experiment_bm25_params.py`）：**top-1 chunk 一次没变，
端到端指标一个字没动**，连 `delta=50`、`min_len=4` 这种荒谬值都一样。
原因完全相同 —— 最终排序主键是 `relevance`，BM25 与稠密通道都只决定"谁能进候选池"。
**重排层才是真正的老板。** 这也是我保留 `k1=1.5 / b=0.75 / delta=0.5` 这三个
文献默认值的依据：不是懒得调，是实测证明它们在这条链路上没有发挥余地。

### 2. 重排里那个"文件名先验"

查询"年假怎么算"时，如果 `leave-policy.md` 命中了"年假"，说明**整篇文档都在讲这个主题**，应当加权。
否则同样提到"年假"的零散段落会把它挤下去。实测这条比单纯调 BM25 参数有效。

### 3. 拒答判定：我踩了三个坑才找到能用的信号

这一节是整个项目最值得讲的部分，因为它展示了**"看起来合理"的方案如何连续失败**。

**坑一：用混合分数做绝对阈值。**
最早我用 `score < 0.3` 判断"有没有依据"，而 `score` 是 RRF 融合分与覆盖率的加权混合值 ——
量纲不可比、也无法跨查询设固定阈值。症状极其尴尬：**引用里明明有正确答案，系统却回答"没有依据"**。

**坑二：用字符覆盖率当判据。**
改用覆盖率（问题实义字符在段落里的占比）后，发现它会被用户多说的词稀释：
问"公司密码要求多少位？多久必须更换一次？"，正确答案的覆盖率只有 0.29 ——
用户问得越啰嗦，分数越低。而完全超纲的"公司股票代码是多少"能蹭到 0.33。
**两个区间重叠，无论阈值定在哪都会错一批。**

**坑三：覆盖率的分母本身是错的。**
中文分词会产出大量 bigram/trigram（"年假没休完" → 年假/假没/没休/休完/年假没/…），
大部分是无意义组合。用它们当"主题词"算覆盖率，等于用噪声当分母。

**最终方案**：两条**语义明确**的信号做 AND：

| 信号 | 含义 | 挡掉什么 |
|---|---|---|
| `relevance ≥ 0.28` | IDF 加权的实义字符覆盖率 | "今天天气怎么样"这类完全无重合的 |
| `longest_span_chars ≥ 2` | 最长**连续**命中字符数 | "公司股票代码"这类只共用"公司/代码"两个字的 |

阈值由 `scripts/calibrate_thresholds.py` 在标注集上网格搜索得到，**零误拒**。

### 4. 权限隔离在检索阶段，而且"无权限"要明说

过滤发生在**检索阶段**而不是生成阶段 —— 没权限的片段根本不进入上下文，这比"生成后打码"安全得多。

但只做过滤还不够，有个容易忽略的漏洞：
无权限用户提问"P4 绩效工资占比"时，如果只过滤，系统会**拿一份别的文档（比如差旅住宿标准）来回答** ——
既答错了问题，又暴露了"公司里确实有这份薪酬文档"。

所以本项目显式做**权限提示**：识别出"问题指向了受限文档"就明确告知，
且判定**从严**（要求覆盖率 ≥ 0.55 且明显高于可见文档），避免误报"你无权访问"把用户搞懵。

### 5. Mock 是"确定性参考策略"，不是"假装回答"

Mock 模式的定位很容易被误解。它不编造内容，而是按固定剧本调用**真实工具**，
最后用工具**真实返回的片段**组织答案。所以：

- 面试现场不赌网络和 API Key；
- 单元测试没有随机性；
- 改检索、改切块时不用花钱。

**换真实模型后，链路、工具、评测口径完全不变。** 这是"双模式"真正的价值。

### 6. 零核心依赖是刻意设计，而且能讲出理由

全部基于标准库：BM25 自己写、嵌入自己做、RRF 自己融合、
mini-YAML 自己解析（约 120 行，覆盖配置文件用到的语法子集）、Web 服务用 `http.server`。

代价是没有自动文档、没有流式输出。收益是 **clone 完就能跑** ——
面试现场被要求"跑一下"时，不需要先等 `pip install` 两分钟。

### 7. 把检索能力接进别人的 Agent（MCP）

前三个前端（CLI / Web / Agent）都只能在本项目内部用。
`python -m docpilot mcp --role public` 起一个 **MCP 服务端**（stdio 传输），
于是 Claude Desktop / Cursor / Cline 只要配一行 JSON，就能把同一份知识库
当工具用 —— 而且引用、拒答、权限隔离的行为**完全一致**，
因为它复用的是同一个 `ToolRegistry`，不是另写一套检索。

```json
{
  "mcpServers": {
    "docpilot": {
      "command": "python",
      "args": ["-m", "docpilot", "--root", "D:\\path\\to\\DocPilot",
               "mcp", "--role", "public"]
    }
  }
}
```

暴露的工具只有两个：`search_docs` 与 `list_documents`（都只读）。

**三个刻意的取舍，都值得被追问：**

| 取舍 | 原因 |
|---|---|
| **手写协议，不引官方 SDK** | stdio 传输就是"一行一条 JSON-RPC 2.0"，我们只需要 `initialize` / `notifications/initialized` / `ping` / `tools/list` / `tools/call` 五个方法，约 200 行。与"零核心依赖"一致：clone 完就能挂 |
| **角色绑在服务端，绝不作为工具参数** | MCP 的调用方是**宿主里的模型**。把 `role` 做成参数等于允许客户端自称 HR 去读薪酬文档，整条检索期权限隔离就废了。所以角色来自 `--role` / 环境变量 / 配置，且 `needs_role` 会在参数校验**之后覆盖**客户端传来的同名字段 |
| **不暴露 `ask`，只暴露检索** | 宿主自己就在跑 Agent。再塞一个自带 ReAct 循环的 Agent 会互相抢决策 —— 双 Agent 反模式。MCP 这一层的职责边界就是"检索" |

`initialize` 的返回里带了 `instructions`，等于一份**跨进程的 SYSTEM_PROMPT**：
告诉宿主 `has_evidence=false` 表示没有依据、应当拒答，`restricted_sources` 非空
表示无权限、不要拿别的文档代替。即使宿主不是我们的 Agent，三条纪律也跟着走。

**提权是被测试锁住的**：客户端在 `arguments` 里塞 `role: "hr"`，
服务端仍是 `public`，结果里 `has_evidence=false`、`restricted_sources=["hr/compensation.md"]`。
这正是 `test_client_cannot_escalate_role` 那条用例。

## 已知坑（都已在代码注释与测试中固化）

这些是开发过程中**真实踩到并修复**的问题。共同特征是：**都不报错，只是悄悄给出错误结论。**

| 坑 | 表现 | 根因与修复 |
|---|---|---|
| **工具结果被截断导致"检索无结果"** | 引用里明明有正确片段，回答却说"没有检索到" | 直接对序列化后的 JSON 做字符截断，把结构切坏了。修复：**缩字段而不是切字符串** + JSON 修复器 |
| **用不可比的混合分数做绝对阈值** | 明明命中正确文档却拒答 | `score` 是 RRF 分与覆盖率的混合值，量纲不可比。修复：改用语义明确的覆盖率 + 连续命中 |
| **覆盖率被用户多说的词稀释** | 问得越啰嗦分数越低，正确答案被判"没依据" | 分母包含无意义 n-gram。修复：IDF 加权的实义片段覆盖率 |
| **n-gram 分词产出纯虚词组合** | `"的了是在"` 产出 `的了`/`了是`/`了是在`，污染倒排索引与 IDF | 中文 n-gram 在字符层生成。修复：n-gram 至少含一个实义字 |
| **实义片段切分"删虚词后拼接"** | 产出 `"年假没休完结转到明年"` 这种不存在的字符串，命中率下降 | 虚词应当**断开**而不是删掉后粘起来 |
| **取第一条 user 消息当问题** | 多轮追问不触发改写、检索用错问句 | ReAct 会先放对话历史。修复：优先认框架自己写的 `问题：` 标记 |
| **排名排序主键选错** | 问"出差住酒店超预算"，无关文档排第一，真正写着"超标部分由个人承担"的掉到第六 | 排序用了含标题命中的混合分。修复：**relevance 作主序**，融合分只做平局打破 |
| **指代词表漏了「那」** | "那最多能结转多少天"不触发改写 | 只放了"那个"。修复：补上单字「那」，并把长度阈值判断去掉（是否依赖上文只取决于有没有指代词） |
| **权限检查误报** | 问"P4 绩效占比"时把"年假折算"也判成受限 | 覆盖率门槛太松。修复：要求 0.55 且明显高于可见文档 |
| **闭包变量在函数内被重新赋值** | `UnboundLocalError: cannot access local variable 'min_relevance'` | 函数内一旦对闭包变量赋值，Python 就把它当局部变量。**闭包变量只读不写** |
| **空注册表是 falsy** | 工具全注册进全局表，传入的注册表为空 | 定义了 `__len__` 的类，空实例为假。修复：显式 `__bool__` |
| **测试夹具打断依赖链** | `the tmp_path_factory fixture is not available` | 覆盖 pytest 内置 `tmp_path` 会打断工厂链 |
| **`tempfile.mkdtemp` 目录无法建子目录** | `PermissionError: [WinError 5]` | 它创建的目录权限是 0o700，受限 Windows 令牌下写不进去 |
| **Tab 缩进检查永远不触发** | YAML 的 Tab 检查形同虚设 | `\t` 被后面的 `strip` 吃掉了。修复：在去空白**之前**检查 |
| **PyYAML 让内置解析器永不被测** | 内置 mini-YAML 的报错路径测不到 | 装了 PyYAML 就永远走它。修复：加 `force_mini` 开关 |
| **一个 BOM 让整条 MCP 会话失败** | 手工造的输入文件让首条 `initialize` 返回 `-32700`，现象是"宿主连不上" | PowerShell 的 `-Encoding utf8` 会写 BOM，而 JSON 解析器不认。修复：读入时 `lstrip("\ufeff")`。**根因藏在第一个字节里**，比报错信息难找得多 |
| **PowerShell 验证接口时中文变乱码** | 所有问题都被拒答，一度以为是服务端 bug | 请求体没显式转 UTF-8 字节，按本地代码页编码了。**是客户端问题** |
| **`chunk_size` 超过段落长度后失效** | `800` 与 `360` 产出的片段数完全相同（都是 75） | 示例文档单段最长 247 字符，`len(candidate) <= chunk_size` 恒成立。**参数有适用区间，不是 bug** |
| **接上管道，评测就崩** | `python -m docpilot eval` 在 Windows 上以退出码 1 结束并报 `UnicodeEncodeError`；同一命令直接跑却完全正常 | 接管道后 Python 不再走控制台的宽字符接口，改按 GBK（cp936）编码输出，`✓`/`✗` 编不出来 —— **崩在最后一行输出上，而不是评测本身**。修复：`core.ensure_utf8_stdio()` 把 stdout 切成 UTF-8 + `errors="replace"` |
| **BM25 换什么参数指标都不动** | 我把 k1/b/delta 从 0.9 扫到 2.4、`delta` 甚至试到 50，复合分、检索命中、幻觉率**一个字没变**，一度以为实验写错了 | 最终排序主键是 `relevance`（词面覆盖率），BM25 **只决定谁能进候选池**。top-1 在 16 个变体里一次没变，只有 `b=0` 会换掉 top-2~4 里约 15% 的片段。**"参数没反应"要分层排查**：先看检索层的 top-1/top-4 集合，再看端到端 |
| **`.env` 写了却完全没生效** | 文档写着"复制 `.env` 并填入真实值"，可填完还是 Mock，而且**一点也不报错** | 代码只读**进程环境变量**，从来没读过 `.env` 这个文件 —— `.env.example` 承诺了一件没实现的事。修复：手写 40 行 `parse_dotenv`，并把优先级定成**命令行 > 环境变量 > `.env` > YAML**，`info` 里显示每一项来自哪一层 |

## 已知限制


1. **拒答是词面启发式，不是语义判断。**
   残余 `hallucination_rate = 0.143`（3/21）。典型失败："公司的股票代码是多少"——
   它与《信息安全规定》里讲"代码"的段落有字面重合（覆盖率 0.58、连续命中 2 字），
   系统分辨不出"文档提到了这个话题"与"文档回答了这个问题"。
   **修它需要语义判定或一次模型判定，而不是继续调阈值** ——
   继续调就是对这 21 条评测集过拟合，换一份文档就失效。

   **这条限制比 0.143 看起来严重得多。** 我另造了 60 条 hard negative
   （与真实事实同构、但文档没答，例如"P6 的期权授予比例"、"加班有加班费吗"），
   同一套逻辑在上面**误答 90.0%**（[79.9%, 95.3%]），而正例误拒仍为 0%。
   也就是说：`0.143` 只代表"简单负例"上的表现；真正的短板是"话题相近但没答案"这一整类。
   分类型的数字见 [docs/架构说明.md 8.5 节](docs/架构说明.md)，复现命令见「常用命令」。

2. **本地嵌入没有语义泛化能力。** 它靠词面哈希，同义改写（"年假"↔"带薪年休假"）依赖手工同义词表。
   表里没有的说法就召回不到。
   **但实测（见设计决策 1）显示：这个限制当前不影响端到端指标** ——
   因为语义信号根本没被判定逻辑使用。所以它是"未来的天花板"，不是"当下的瓶颈"。

3. **检索有粒度问题。** 问题跨小节时可能命中相邻小节（评测集 `single-01`）。
   根因是 chunk 级覆盖率低估了"答案分散在多段"的情况。

4. **指代消解是规则式的 —— 而且这条在真实模型下暴露过，已修复。**
   原实现里 `Agent.ask` 是 `if context and history is None`，意味着调用方一旦传入
   `history`（评测就是这么调的），**历史根本不会进 prompt**；配上 `reset=True`，
   模型看到的就是一句孤立的问题。实测 `multi-02/03` 复合分掉到 **0.25**，
   模型回答「你用了"它"，但没有上文」——**这是正确行为，错在框架没把上文给它**。

   修复：历史**无条件**渲染进 prompt（模型自己消解指代），规则式改写降级为兜底；
   同时修掉 `_extract_topic`（原来取"最长的中文连续片段"，把「密码有什么复杂度要求」
   取成「密码有什么复杂」，改写结果不可用）。修复后 `multi-01/02/03` **全部 1.0**。

5. **评测集是文件级的，分辨不出片段级的改动。**
   我实测过：把 `chunk_size` 从 360 改成 150（片段数 75 → 111，**索引规模涨了 48%**），
   端到端指标**一个都没变**。
   因为 `expected_sources` 标的是文件（`hr/leave-policy.md`），
   而切块只改变"文件内部怎么分"，不改变"命中哪个文件"。
   **指标的作用层级与参数的作用层级不匹配** —— 想观察这类改动，评测必须精确到 chunk 级。

6. **`rag.chunk_size` 在本语料上近乎失效。** 示例文档单个自然段最长只有 247 字符，
   当 `chunk_size > 247` 时贪心拼接的判定恒为真，切块粒度实际被 **Markdown 小节结构**主导。
   实测 `chunk_size=800` 与 `360` 产出的片段数**完全相同（都是 75）**。
   这不是 bug，而是"参数有适用区间" —— 用长段落可以验证参数确实生效。
   详见 [docs/架构说明.md](docs/架构说明.md) 第 4.1.1 节。

7. **规模未经检验。** 75 个片段、8 篇文档下用纯 Python 内存索引很快；
   到十万级 chunk 必须换成真正的向量库与倒排索引。

8. **没有流式输出。** Web 界面是"等全部生成完再显示"。

9. **MCP 暴露后，提示词注入成了新的攻击面。** 检索结果会**原样进入宿主模型的上下文**，
   所以文档正文里写的"忽略之前的指令"不再受本项目的 `SYSTEM_PROMPT` 约束 ——
   那三条纪律只对**我们自己的 Agent** 有效。目前的缓解只有两条：
   工具全是只读（`readOnlyHint`，宿主可免确认），以及返回值里只有数据、没有指令。
   真要上线，还需要在索引侧做注入检测，或在宿主侧把检索内容显式标成 data。

> 第 5、6 条来自一次**推翻了自身假设的实验** —— 我原本在文档里预测
> "片段太大会稀释相关性"，实测发现指标根本不变。把这个反例如实记下来，
> 比留一个听起来合理的猜测更有价值。复现：`python scripts/experiment_chunk_size.py`
