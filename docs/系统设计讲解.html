01 · 问题定义

企业问答的失败模式和聊天机器人不同

聊天机器人答错
顶多没用
用户重新问一次，成本可以忽略
企业知识库答错
是一条事故
答错一条制度、金额或时限，员工照着执行，责任在公司

所以真正需要解决的是两件事：让它在没有依据时明确拒答；让每一句结论都能指回原文。

这类失败有一个共同点：它不报错。系统只会安静地给出一个看起来很有依据的错误结论 —— 所以"设计"和"度量"必须一起做。
01 · 问题定义

设计目标与约束四个目标，对应四件可以被检查的事

目标设计手段为什么不用更简单的做法
可溯源引用标号由框架生成并校验，不采信模型给出的结构化引用让模型"顺手写个来源"，它会写不存在的来源
可拒答两条语义明确的信号做 AND，阈值网格搜索标定用混合分数做绝对阈值，失败是随机的、无法解释
可隔离权限在检索阶段过滤，无权限片段不进上下文生成后再打码，一处路径遗漏就泄漏
可回归离线基线做 CI 门禁，真实模型做验收只用真实模型：不确定、要花钱、CI 无法稳定复现

约束是"零核心第三方依赖 + 离线可跑"：任何一台装好 Python 的机器上克隆下来即可运行，代价是所有能力都要自己实现。

这四条目标最后都落成了可以自动判定的事：一个指标、一条门禁、或一个单元测试。

▼ 产物只读：倒排表 / 向量表 / chunks 字典 / 权限元数据
② 在线问答每次提问
检索 → 融合 → 重排 → 证据判定 → 生成 → 引用映射
分层
索引层（离线）／检索层／判定层／生成层／收尾层，每层一个文件
共用
CLI、Web 接口、Agent 三个入口共用同一份知识库与同一套工具注册表，只是外壳不同
可测
建库与检索都不依赖模型，所以能在进程内确定性复现
离线的产物决定在线的上限：切块把一句话劈开，后面的检索和重排都救不回来。

倒排表负责"字面对得上"，向量表负责"说法不同也能召回"，chunks 字典供引用映射，权限元数据是隔离的依据。

一个有意义的负结果：示例语料单段最长 247 字符，当 chunk_size > 247 时贪心拼接判定恒为真， 切块粒度实际由 Markdown 小节结构决定 —— 实测 chunk_size=800 与 360 产出的片段数完全相同。 这说明该参数存在适用区间，而不是"调了没用"。
另一个细节：中文 n-gram 会跨词边界产出纯虚词组（"的了是在" → 的了/了是）， 污染倒排表与 IDF，所以 n-gram 至少要含一个实义字。

一份数据，两种形态
给模型看的是摘要（缩字段而非截字符串）；给框架用的是完整 payload（用于引用映射与降级）
一个容易误读的写法：for ... else 里的 else 属于 for， 只在"跑满最大步数且从未 break"时执行 —— 用它检测步数预算耗尽，与循环内的工具额度检查配合覆盖两种预算。
模型只负责"决定下一步做什么"，证据判定、引用映射、失败兜底都在框架里，因此可以被单元测试断言。
03 · 关键设计

检索：为什么必须两路，以及为什么只按排名融合

① 权限
先算可访问集合
allowed_ids
→
② 稀疏 BM25
倒排取候选（与权限求交）
打分取前 8
③ 稠密
查询向量与全库相似度
取前 8
→
④ RRF 融合
Σ w/(k+rank)
k=60 · w=(1.2, 1.0)
两路各自的强弱
企业文档的关键信息多是低频精确词（制度编号、金额、时限），纯语义容易糊掉；而用户提问又常口语化，纯关键词会漏。两者弱项互补。
融合只用排名
BM25 分数无界、余弦相似度在 [-1,1]，量纲不可比。只用名次融合可以绕开对齐问题，也更容易解释"为什么它排前面"。
权限在检索之前生效：无权限片段根本不会进入打分，更不会进入上下文。
03 · 关键设计

重排：三个可解释的信号，并顺带产出拒答依据

信号权重衡量什么
IDF 加权实义覆盖率0.55命中的是"稀有实义词"还是"到处都是的通用词"
字符覆盖率0.25问题的实义字符有多少出现在该段落里
最长连续命中字符数0.20是"整句对上"，还是"只撞了两个零散字"

排序主键用的是这个相关性分数，融合分只在平局时用来打破并列。

一个被修正的设计错误：早期以混合分数排序，而它含"标题命中"这一项 —— 问"出差住酒店超预算怎么办"时，标题里带"常见问题"的入职文档排到了第一， 真正写"超标部分由个人承担"的差旅制度掉到第六。根因是排序主键选了一个不可解释的量。
重排不只是精排：relevance 与 longest_span_chars 都由它产出，后面的证据判定完全依赖这两个数。
03 · 关键设计

证据判定：拒答与误答的分界点

has_evidence =
  bool(results)
  and not restricted    # 权限优先
  and best_relevance >= 0.28  # 相关性是否达标
  and best_span >= 2        # 不是零散撞字
标注集实测relevance 区间最长连续命中
应当回答0.444 ~ 0.7204 ~ 5
应当拒答0.000 ~ 0.579（与上组重叠）0 ~ 2（干净分开）
单看相关性分不开这两组，必须再加"最长连续命中" —— 这就是为什么判定用 AND 而不是单一阈值。
03 · 关键设计

引用：标号由框架生成，不采信模型给的来源

模型产出
答案正文带上 [1]、[2] 标号
框架产出
按检索结果的实际顺序，把 [1] 映射到真实的文档与章节，并校验标号范围
情况处理方式
标号都在范围内按检索顺序生成映射
标号越界（只检索到 3 条却写 [9]）记入调用轨迹，不臆造来源
完全没有标引用补上相关度最高的前几条来源，而不是留空
判定为应当拒答不附引用 —— 否则用户会以为系统在拿这些片段当依据
实测引用有效性 1.000（零伪造引用），真实模型复测同样为 0 条伪造 —— 这一点不依赖模型是否配合。
03 · 关键设计

权限：三个位置，一个原则

① 检索入口
allowed_ids
过滤掉无权片段
无权内容不参与打分
② 证据判定
受限文档识别
问题指向无权文档时
明确告知，不拿别的文档凑答案
③ 收尾
权限类拒答文案
且不附引用
只做过滤是不够的：无权限用户问"P4 职级绩效占比"，系统会拿差旅住宿标准来回答 —— 既答错了问题，又间接暴露了"确实存在一份薪酬文档"。因此增加了"受限文档识别"。

判定刻意从严：覆盖率足够高且明显优于可见文档时才提示无权限 —— 误报"你无权访问"会让用户以为系统故障。

原则是权限属于检索属性，而不是生成属性：在检索阶段就过滤，比生成后再打码可靠得多。
03 · 关键设计

收尾：失败也要给出可用的结果

环节做法设计理由
降级调用预算用尽时，用已检索到的片段拼一个"部分结论"不空手而归；读完整 payload 而不是给模型看的摘要，否则引用信息已被压缩掉
拒答识别识别"没有依据 / 证据不足 / 无权限"三类识别错了，拒答准确率与误拒率两个指标都会失真
会话记忆保留最近若干轮，供下一轮消解指代多轮追问的上下文必须真正进入提示词，而不是只给工具用

这三个环节全部由代码完成，不依赖模型自觉 —— 所以能用单元测试锁住行为。

把"模型该做的"和"框架该做的"划清，是这类系统可测试、可复现的前提。
04 · 度量与边界

指标设计：四类互相制衡，而不是一个总分

指标实测门禁为什么不能去掉
复合分0.931≥0.75四项加权的整体视图
检索命中0.952≥0.85检索层失效时，生成层再强也没有意义
引用有效性1.000≥0.95零伪造引用，是本系统最核心的对外承诺
拒答正确率0.857≥0.70该拒时是否拒；门禁刻意低于当前能力，避免长期红灯被忽略
误拒率0.000≤0.15该答却拒是另一种失败，与幻觉同等严重

门禁阈值按实测能力标定，而不是设一个乐观目标：把门槛定在能力之上，等于没有门槛。

拒答必须双向考核。只统计"幻觉"会让系统越来越保守，最后变成什么都不肯答 —— 那同样是失败。

32%

口径需要说清楚：89.8% 是"离线基线中词面判定的误判率"，不是"系统整体误答率"。 离线基线把判定结论当作唯一依据，判定错一次就误答一次；真实模型在读取片段后会自行判断。
这个对比本身就给出了结论：判定能力在模型层，不在检索层 —— 优化方向应是更换判定信号，而不是继续调阈值。
04 · 度量与边界

验证三：接真实模型后，暴露了三个离线测不到的问题

现象根因修复结果
多轮追问得分降到 0.25，模型回答"没有上文"历史仅在未显式传入时才渲染进提示词；评测恰好显式传入了历史，于是模型只看到一句孤立问题历史无条件进入提示词，三条多轮用例全部回到 1.0
无权限时回答成"没有找到依据"系统提示词没有提及受限来源字段；这句提示原本只写死在离线基线的回答模板里明确回答"当前角色没有访问该文档的权限"
9 条正确拒答被统计成误答拒答识别是一张按离线基线表述写的关键词表，覆盖不到真实模型的措辞只看结论句 + 模式匹配：召回 87.8% → 98.6%，误判 7.3% → 3.6%
修复后真实模型（deepseek-flash）21 条：复合分 0.9881，检索命中 1.000，拒答正确 1.000，伪造引用 0 条。
结论：离线基线能验证链路，不能验证判断力；而且"评测工具本身"也需要被评测 —— 否则指标失真比效果差更危险。

04 · 度量与边界

已知边界

  • 判定偏字面：遇到"话题相近但文档没有答案"的提问会放行。已验证调参的上限只有约三分之一，正确的修法是更换判定信号。
  • 评测集是文件级的：分辨不出切块这类"文件内部"的改动。实测调整切块粒度时，端到端指标没有变化 —— 指标的作用层级与参数的作用层级不匹配。
  • 规模未经验证：75 个片段可以全量计算，到十万级必须换成向量库与倒排索引，当前实现不具备该性能特征。
  • 拒答识别仍依赖表述形式：已从 87.8% 提升到 98.6%，彻底的做法是引入判定模型。
  • 多轮指代消解是规则式的：靠指代词表 + 主题词提取，复杂指代（"它的第二条呢"）处理不了，生产上应换成一次模型调用。
这些限制都写在仓库 README 与架构文档里 —— 一个系统的可信度，很大程度上取决于它的作者如何描述它的边界。
04 · 度量与边界

如果继续投入，优先级是这样排的

序方向理由预期收益
1把判定移到模型层已验证：小规模实验中误答可压到 0，代价是每次查询多一次调用直接解决最大的短板
2把评测的拒答识别换成判定模型当前依赖表述形式，会让所有指标失真让度量本身可信
3扩充留出集负例当前负例样本量导致置信区间偏宽结论更稳，可作为回归基线
4换真实向量模型与重排器收益待验证：此前的消融显示，单独替换嵌入对端到端指标没有影响优先级最低 —— 因为它不解决判定问题
排序依据是"是否直接作用于已知短板"，而不是实现难度或技术新颖度。
